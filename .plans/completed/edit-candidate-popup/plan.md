# 编辑文件模式：候选框跟随光标

编辑文件（`duanyan FILE`）时，输入框占满整个正文区，候选固定画在输入框最底部。
光标在屏幕上方时，视线要在光标和屏幕底部之间来回跳。改为在光标下一行弹出一个
浮动候选框。

只改编辑文件模式。带历史记录的普通全屏模式（输入框随内容伸缩，候选紧跟正文）
和 inline 模式保持不变。

## 1. 布局

`draw_fullscreen` 在 `Mode::Edit` 下：

- 文本区占满输入框内部的全部高度，不再为候选预留 `cand_rows` 行。滚动逻辑
  （`scroll_offset`）不变。
- 先画文本，再在文本之上画候选框：`Clear` + 圆角 `Block`（边框色 `t.border`，
  背景 `t.bg`），框内调用现有的 `draw_candidates`。没有候选时不画。
- 光标行本身不被遮挡，右对齐的 raw input 照常显示。

## 2. 候选框的位置和尺寸

纯函数 `popup_rect(anchor: Position, size: (u16, u16), bounds: Rect) -> Option<Rect>`，
`bounds` 是输入框的内部区域（`block.inner(input)`）。

- **锚点**：preedit 起点所在的列，行取光标所在行。preedit 起点比 rime 的光标
  稳定，打字时框不会左右移动。preedit 折行导致起点和光标不在同一行时，列取
  文本区左边界。`layout_cells` 已经在排版 preedit，顺带返回起点的 `(行, 列)`。
- **水平**：框的左边框在锚点列减 1，候选序号自带的前导空格正好落在 preedit
  起点下方。右侧放不下时整体左移贴住 `bounds` 右边界；比 `bounds` 还宽时取 `bounds` 宽度，
  放不下的候选按现有规则截掉（下一页可见）。
- **垂直**：默认放在光标行的下一行。下方剩余行数不够而上方够时，翻到光标行
  上方（框的底边紧贴光标行）。两边都不够时放在空间较大的一边并截短：竖排少显示
  几个候选，横排至少要 3 行，不足则不画。
- **尺寸**：新增 `candidates_size(ctx, snap)`，和 `draw_candidates` 共用每个候选
  的宽度计算（序号、文字、可选注释）。
  - 横排：所有候选宽度加间隔，再加页码指示 `‹ n ›` 的宽度；高度 1。
  - 竖排：最宽的一个候选加页码指示宽度；高度 `candidate_rows`。
  - 加上两侧边框和右侧 1 列内边距（序号自带前导空格，左侧不再留白）。

## 3. 鼠标

`App::mouse` 先检查 `hits.candidates` 和翻页箭头，再检查文本区，所以点击框内
候选、翻页照常生效。点在框的边框或空白处会落到被遮住的文本上，但候选框只在组字
时出现，而组字时点击文本本来就被忽略，所以不需要额外的命中区域。

## 4. 测试

- 单元测试 `popup_rect`：正常放在下方；右侧溢出左移；比 `bounds` 宽；底部翻到
  上方；上下都不够时截短 / 不画。
- 单元测试 preedit 起点：同行、折行两种情况。
- `scripts/e2e.sh` 的编辑文件部分新增一步：打开多行文件，在第一行输入 `nihao`，
  断言候选（`你好`）出现在光标行的下一行而不是屏幕底部；`alt+>` 跳到末尾再
  输入，断言候选出现在光标行上方。
- `cargo test`、`cargo clippy --all-targets`、`scripts/e2e.sh` 全部通过。
