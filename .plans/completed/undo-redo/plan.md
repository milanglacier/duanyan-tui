# 撤销与重做

给输入框加上撤销和重做。inline（`--stdout`）、`--stdout --fullscreen`、全屏
scratch 和编辑文件模式共用同一个 `App` 和 `Buffer`，实现一次，四种模式行为一致。

## 1. 范围

- 只撤销输入框里的文本修改。删除历史记录、rime 的组字状态、中英文切换都不在
  范围内。
- 只跟踪当前 buffer：scratch 模式提交后清空撤销历史，不能撤销找回已提交的文本
  （它已经在历史记录里）。编辑文件模式以打开时的内容为起点。
- 重做是线性的：撤销后做了新的编辑，就清空重做栈。不做撤销树。
- 撤销栈最多 1000 步，超出时丢掉最早的，不提供配置项。

## 2. 按键

`[keybinding.input]` 新增：

```toml
undo = ["ctrl+z", "ctrl+/", "ctrl+_"]
redo = ["ctrl+y", "alt+_"]
```

终端上的限制：

- 没有 kitty 键盘协议时，ctrl+/ 和 ctrl+_ 都发 `0x1F`，crossterm 报告为
  ctrl+7。`legacy_alias` 已经把两者映射到 ctrl+7，绑定到同一个动作不算冲突。
- ctrl+? 在多数终端里发 `0x7F`，和 Backspace 相同，也有终端发 `0x1F`，所以不放
  进默认键位。`legacy_reachable` 现在把 ctrl+? 算作可达，改为不可达，用户自己
  绑定时帮助页会标出“当前终端不可用”。
- ctrl+z：raw mode 关掉了 ISIG，不会挂起进程。
- 所有按键先交给 rime，rime 处理了的键不会触发撤销。

## 3. 记录方式

`Buffer` 的所有修改都经过一个内部函数，把每次修改记成一条差异：位置、删掉的
文本、插入的文本、修改前后的光标。不存整段文本的快照，编辑文件模式下文件可能
很大。没有改动文本的操作（如在开头按 backspace）不记录。

撤销把差异反向应用，光标回到修改前的位置；重做正向应用，光标回到修改后的位置。

## 4. 合并粒度

每一步撤销对应一条差异。能合并的只有三种连续操作：

- **直接输入的字符**（英文模式下 rime 没处理、由端砚插入的字符）：连续输入合并
  为一步，空格不断开。ASCII 标点算作当前这一步的结尾，下一个字符另起一步。
- **连续的 backspace** 合并为一步。
- **连续的 delete** 合并为一步。

其余修改各自一步：rime 上屏、换行、kill_word / kill_to_start / kill_to_end、
粘贴、删除鼠标选区、从历史取回、scratch 模式下 Esc 清空。

光标移动（按键或鼠标点击）、撤销、重做和任何不可合并的修改都会结束当前这一步。
合并状态记在 `Buffer` 里，由它的移动和编辑方法维护，`App` 不需要额外记录。

## 5. 与其他功能的交互

- **组字时**：rime 没处理撤销 / 重做键时直接忽略，避免 preedit 和文本错位。
- **鼠标选区**：任何按键都会结束选区，撤销 / 重做也一样。
- **编辑文件模式**：撤销回打开时的内容后，文本与原文件相同，Esc 直接退出，不需
  要按第二次。
- **scratch 模式 Esc 清空**：可以撤销，防止误按。

## 6. 测试

- `buffer.rs` 单元测试：合并规则（空格不断开、标点断开、backspace / delete 合并、
  光标移动断开）、撤销后光标位置、新编辑清空重做栈、上限、`set_text` / `take`
  清空撤销历史。
- `app.rs` 单元测试：组字时忽略、scratch 提交后不能撤销、Esc 清空可撤销、编辑
  文件模式撤销回原样后 Esc 直接退出。
- `keys.rs`：ctrl+? 在传统模式下不可达。
- `scripts/e2e.sh`：全屏 scratch 和 inline `--stdout` 下用 `C-z`、`C-_`、`C-y`、
  `M-_` 验证撤销和重做。ctrl+/ 在 KKP 下与 ctrl+_ 的区分只能靠单元测试。
